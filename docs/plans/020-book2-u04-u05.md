# Plan 020 — Book 2 U04 "Sets, Tuples & Sorting" + U05 "Searching & Complete Search"

**Goal:** Ship the two Term-1 tool-building units that give students their core searching/dedup/ordering
toolkit — `unit-04-sets-tuples-sorting` (introduces the FEATURES `set-literal`, `set-ops`, `tuple`,
`sorted-key`) and `unit-05-searching-complete-search` (introduces the TECHNIQUES `binary-search`,
`complete-search`) — on the `solve(data:str)->str` contract, following the established Book-2 unit pattern.

**Architecture:** Two units, each the standard Book-2 set (lesson/exercises/solutions/teacher-notes/manifest).
U04's introduced concepts are AST-detectable **features**, but `concept-scan` is **one-directional** — it only
reds a used-but-UNLISTED concept or an untaught method; it does NOT verify that an introduced feature is
actually used. So authoring must use the exact detected forms (see Global Constraints) AND the content gate
MANUALLY confirms (ad-hoc `detect()`) that each of the four features is detected. U05's are reviewer-enforced
**techniques** (scanner-invisible in BOTH directions); binary-search is now an INTRODUCED technique here, so
`lo/hi/mid` on a sorted list is finally permitted (it was banned through U03). Graded exercises are
`solve(data)` problems that REQUIRE the unit's tool (U04: membership/dedup/tuple-keying/custom-sort;
U05: search or fixed-depth enumeration). Wire each into ci-local via the existing Book-2 per-entry block
(already iterates all authored units).

**Tech Stack:** Jupyter notebooks (nbformat), `tools/` verification package, `scripts/ci-local.sh`,
`py4kids-tools --book book2` checks; Python 3 standard library only (no imports needed for these units).

**Spec:** `docs/designs/001-book2-algorithms.md` (§4 unit anatomy, §5 two-tier concepts, §7 U04/U05 —
incl. the U05 closure NOTE: complete search is fixed-depth nested-loop enumeration ONLY; subset/permutation
GENERATION is deferred to U09/U11); `book2/syllabus.md`; `book2/curriculum/coverage-map.yaml` (U04/U05
entries); `book2/curriculum/concepts.yaml`; **plan 018/019 (the established Book-2 unit pattern — all of it
transfers)**; the plan-019 content-gate lessons (mutation-test asserts: off-by-one, wrong-aggregate/boundary,
self-pair, first-vs-last, and **decisive-last-AFTER-SORT**).

## Global Constraints

Copied verbatim from the design + registry; every task's requirements implicitly include this section.

- **Contract:** every reference solution is a pure `solve(data: str) -> str`; ZERO `input()` in any
  executable cell; the submission wrapper `import sys; print(solve(sys.stdin.read()))` appears ONLY in a
  `no-exec`-tagged lesson cell or teacher-notes (NEVER in solutions.ipynb — exec-solutions runs every cell).
  Deterministic (no `random`). Solutions run top-to-bottom clean.
- **Student cells are EMPTY** (`''`) — matching U01/U03 (and now U02). No `def solve(data): ...` stubs.
- **U04 `set-ops` MUST be introduced via `.add` / `.discard` / `.remove`** on a variable assigned from a
  set literal `{…}` or `set()` (the scanner only credits set-ops for those methods on a known set name),
  and/or the difference operator `set_a - set_b` (an `ast.Sub` on set operands — set-ops WITHOUT bitwise).
  **NEVER use `&` / `|` / `^`** on sets (they fire the `bitwise-ops` detector → used-but-unlisted RED,
  since bitwise-ops is not introduced until U11). **NEVER use `.union` / `.intersection` / `.difference`**
  method names (not in the scanner's taught-method set → flagged as untaught methods). Teach union /
  intersection conceptually and implement them with a loop + `.add` (`for x in a: if x in b: out.add(x)`)
  or with `-`.
- **U04 `set-literal`** via a real `{a, b, c}` literal — `set()` alone does NOT fire it (only an `ast.Set`
  node does; `set()` merely marks a known set name), so at least one `{…}` literal must appear per notebook.
  **Keep each set's assignment and its `.add`/`.discard`/`.remove` in the SAME code cell** — the scanner
  parses each cell independently, so `set_names` does not persist across cells (assignment in one cell,
  mutation in another → no set-ops credit). **`tuple`** via tuple literals `(a, b)`, `return (lo, hi)`, or
  unpacking `for a, b in pairs:`; **`sorted-key`** via `sorted(seq, key=fn)` with a **named** key function
  (`def by_second(t): return t[1]`) — no `lambda` (reviewer-enforced: the scanner credits `key=` either way,
  but lambda is not a taught Book-1 feature). Also avoid generator expressions inside `all(...)`/`any(...)`
  etc.: a genexp fires the `comprehension` feature (U09) → premature.
- **U05 `binary-search`** iterative `lo/hi/mid` on a sorted list is now ALLOWED (introduced here);
  **`complete-search`** is fixed-depth nested loops over all pairs/triples/candidates ONLY — NO recursive
  or bitmask subset/permutation GENERATION (closure: recursion=U09, bitmask=U11), and **NO converging
  two-index / two-pointer scan** (a sorted `lo`/`hi` pair walking inward is the `two-pointers` technique,
  introduced at U14 — premature and scanner-invisible). Pair-sum / pair-property problems use either a
  nested-loop enumeration (O(n²)) or sort-then-`binary-search`-the-complement (O(n log n), this unit's own
  technique), never the converging scan.
- **Closure:** only Book-1 + U01–U04 concepts (plus each unit's own introduces). NO untaught methods
  (`.join`/`.splitlines`/`.index`/`.count`/`.find`/`.pop`/`.union`/…); NO untaught builtins — the scanner's
  taught builtins are exactly `{len, min, max, sorted, sum, abs, round}`, so **`all`/`any`/`enumerate`/
  `zip`/`reversed`/`map`/`filter`/`set`-as-dedup-in-comprehension are BANNED** (bare-name calls slip the
  scanner → author-enforced). `concept-scan --book book2` must be clean.
- **Two-tier `practices`:** scanner-derived FEATURES (incl. `str-split`) + hand-listed TECHNIQUES
  (`input-parse`, and in U05 `complete-search`/`binary-search` are introduces not practices). `practices`
  ∩ `introduces` = ∅. manifest == coverage-map exactly.
- **Rich, laddered problem sets:** ≥ 8 `## Exercise N` per unit (tooling counts `^## Exercise \d+`),
  each with Sample Input / Sample Output / Constraints; ≥ 2 cell-tagged `stretch` (heading "Challenge");
  every non-vacuous assert set includes sample + crafted edge cases; the decisive value is exercised at the
  LAST position (and, for any sort-then-scan solution, the decisive case is last AFTER sorting).
- **teacher-notes:** exactly the five heading strings `## Goals` / `## Pacing` / `## Common mistakes` /
  `## Discussion prompts` / `## Differentiation` (structure-check matches them verbatim — NOT "Learning
  goals"; no `## Rubric`/`## Grading`, those are project/checkpoint-only), a per-exercise Big-O line, and a
  pacing plan covering all allocated lessons (U04 = 2, U05 = 3).

## Out of scope

- No tooling changes (infra + per-entry ci-local wiring already exist; new unit dirs are auto-covered).
- No checkpoint (CP1 is plan 021 — it assesses U01–U05 and needs both units merged first).
- No `comprehension` feature (U09's introduce) — even though set/dict comprehensions are idiomatic dedup;
  U04 dedups with an explicit loop + set to stay in closure.
- **Verification is NOT out of scope:** Phase C is the named verification phase (blind-solve + mutation +
  full ci-local + 4-way content gate).
