# Plan 020 — Book 2 U04 "Sets, Tuples & Sorting" + U05 "Searching & Complete Search"

**Goal:** Ship the two Term-1 tool-building units that give students their core searching/dedup/ordering
toolkit — `unit-04-sets-tuples-sorting` (introduces the FEATURES `set-literal`, `set-ops`, `tuple`,
`sorted-key`) and `unit-05-searching-complete-search` (introduces the TECHNIQUES `binary-search`,
`complete-search`) — on the `solve(data:str)->str` contract, following the established Book-2 unit pattern.

**Architecture:** Two units, each the standard Book-2 set (lesson/exercises/solutions/teacher-notes/manifest).
U04's introduced concepts are AST-detectable **features** — `concept-scan` enforces that each is genuinely
USED in the unit — so the content must use the exact detected forms (see Global Constraints). U05's are
reviewer-enforced **techniques** (scanner-invisible); binary-search is now an INTRODUCED technique here, so
`lo/hi/mid` on a sorted list is finally permitted (it was banned through U03). Graded exercises are
`solve(data)` problems that REQUIRE the unit's tool (U04: membership/dedup/tuple-keying/custom-sort;
U05: search or fixed-depth enumeration). Wire each into ci-local via the existing Book-2 per-entry block
(already iterates all authored units).

**Tech Stack:** Jupyter notebooks (nbformat), `tools/` verification package, `scripts/ci-local.sh`,
`py4kids-tools --book book2` checks; Python 3 standard library only (no imports needed for these units).

**Spec:** `docs/designs/001-book2-algorithms.md` (§4 unit anatomy, §5 two-tier concepts, §7 U04/U05 —
incl. the U05 closure NOTE: complete search is fixed-depth nested-loop enumeration ONLY; subset/permutation
GENERATION is deferred to U09/U11); `book2/syllabus.md`; `book2/curriculum/coverage-map.yaml` (U04/U05
entries); `book2/curriculum/concepts.yaml`; **plan 018/019 (the established Book-2 unit pattern — all of it
transfers)**; the plan-019 content-gate lessons (mutation-test asserts: off-by-one, wrong-aggregate/boundary,
self-pair, first-vs-last, and **decisive-last-AFTER-SORT**).

## Global Constraints

Copied verbatim from the design + registry; every task's requirements implicitly include this section.

- **Contract:** every reference solution is a pure `solve(data: str) -> str`; ZERO `input()` in any
  executable cell; the submission wrapper `import sys; print(solve(sys.stdin.read()))` appears ONLY in a
  `no-exec`-tagged lesson cell or teacher-notes (NEVER in solutions.ipynb — exec-solutions runs every cell).
  Deterministic (no `random`). Solutions run top-to-bottom clean.
- **Student cells are EMPTY** (`''`) — matching U01/U03 (and now U02). No `def solve(data): ...` stubs.
- **U04 `set-ops` MUST be introduced via `.add` / `.discard` / `.remove`** on a variable assigned from a
  set literal `{…}` or `set()` (the scanner only credits set-ops for those methods on a known set name),
  and/or the difference operator `set_a - set_b` (an `ast.Sub` on set operands — set-ops WITHOUT bitwise).
  **NEVER use `&` / `|` / `^`** on sets (they fire the `bitwise-ops` detector → used-but-unlisted RED,
  since bitwise-ops is not introduced until U11). **NEVER use `.union` / `.intersection` / `.difference`**
  method names (not in the scanner's taught-method set → flagged as untaught methods). Teach union /
  intersection conceptually and implement them with a loop + `.add` (`for x in a: if x in b: out.add(x)`)
  or with `-`.
- **U04 `set-literal`** via `{a, b, c}` literals (or `set()`); **`tuple`** via tuple literals `(a, b)`,
  `return (lo, hi)`, or unpacking `for a, b in pairs:`; **`sorted-key`** via `sorted(seq, key=fn)` with a
  **named** key function (`def by_second(t): return t[1]`) — no `lambda` (not a taught Book-1 feature).
- **U05 `binary-search`** iterative `lo/hi/mid` on a sorted list is now ALLOWED (introduced here);
  **`complete-search`** is fixed-depth nested loops over all pairs/triples/candidates ONLY — NO recursive
  or bitmask subset/permutation GENERATION (closure: recursion=U09, bitmask=U11).
- **Closure:** only Book-1 + U01–U04 concepts (plus each unit's own introduces). NO untaught methods
  (`.join`/`.splitlines`/`.index`/`.count`/`.find`/`.pop`/`.union`/…); NO untaught builtins — the scanner's
  taught builtins are exactly `{len, min, max, sorted, sum, abs, round}`, so **`all`/`any`/`enumerate`/
  `zip`/`reversed`/`map`/`filter`/`set`-as-dedup-in-comprehension are BANNED** (bare-name calls slip the
  scanner → author-enforced). `concept-scan --book book2` must be clean.
- **Two-tier `practices`:** scanner-derived FEATURES (incl. `str-split`) + hand-listed TECHNIQUES
  (`input-parse`, and in U05 `complete-search`/`binary-search` are introduces not practices). `practices`
  ∩ `introduces` = ∅. manifest == coverage-map exactly.
- **Rich, laddered problem sets:** ≥ 8 `## Exercise N` per unit (tooling counts `^## Exercise \d+`),
  each with Sample Input / Sample Output / Constraints; ≥ 2 cell-tagged `stretch` (heading "Challenge");
  every non-vacuous assert set includes sample + crafted edge cases; the decisive value is exercised at the
  LAST position (and, for any sort-then-scan solution, the decisive case is last AFTER sorting).
- **teacher-notes:** exactly five headings (Learning goals / Pacing / Common mistakes / Discussion prompts /
  Differentiation), a per-exercise Big-O line, and a pacing plan covering all allocated lessons
  (U04 = 2, U05 = 3).

## Out of scope

- No tooling changes (infra + per-entry ci-local wiring already exist; new unit dirs are auto-covered).
- No checkpoint (CP1 is plan 021 — it assesses U01–U05 and needs both units merged first).
- No `comprehension` feature (U09's introduce) — even though set/dict comprehensions are idiomatic dedup;
  U04 dedups with an explicit loop + set to stay in closure.
- **Verification is NOT out of scope:** Phase C is the named verification phase (blind-solve + mutation +
  full ci-local + 4-way content gate).

**Interfaces:**
- Consumes: Book-1 + U01–U03 concepts (input-parse, str-split, for-loop, list-literal, in-operator,
  list-sort, def-function, comparison, dict for counting).
- Produces: the four features `set-literal`, `set-ops`, `tuple`, `sorted-key` (available as prereqs for
  U05 and later units).

- [ ] **A1 — lesson.ipynb.** Open on a contest hook (e.g. "how many DISTINCT names appear across two
  rosters, and who is in both?"). Teach, in order: (1) sets — `{…}` / `set()`, O(1) membership with `in`,
  dedup by adding into a set; (2) set operations WITHOUT operators — union/intersection/difference explained,
  implemented via loop + `.add` and via `-`; (3) tuples as immutable records / composite keys
  `(surname, first)`, unpacking `for a, b in rows:`; (4) `sorted(seq, key=by_second)` with a named key
  function, incl. sorting tuples by a chosen field and descending via negation. Include a `no-exec`-tagged
  cell showing the submission wrapper. Every executable lesson cell uses only the detected/closure-safe
  forms above.
- [ ] **A2 — exercises.ipynb.** ≥ 8 `## Exercise N`, each a `solve(data)` problem that REQUIRES the tool:
  dedup/count-distinct, membership-filter, in-both / in-first-not-second, tuple-record sorting
  (sort people by score desc then name asc), keep-top-k by key, group-and-pick. ≥ 2 `stretch`. Student
  code cells EMPTY. Each problem states Sample I/O + Constraints; put the decisive value last (and last
  after sorting for sort-based ones).
- [ ] **A3 — solutions.ipynb.** Mirror `## Exercise N`; pure `solve(data)`; each uses the exact detected
  forms (set literals + `.add`/`.discard`/`-`, tuple literals/unpacking, `sorted(key=named_fn)`). Inline
  asserts: sample + crafted edge cases that KILL off-by-one, wrong-aggregate/boundary (tie, empty-overlap),
  self-pair where relevant, and decisive-last-after-sort for every sort-then-scan solution.
- [ ] **A4 — teacher-notes.md.** Five headings; per-exercise Big-O (membership O(1), dedup O(n),
  sort O(n log n)); 2-lesson pacing (L1 sets+dedup+membership; L2 tuples+custom sort); project hook;
  common mistakes (using `&`/`|`; mutating a set while iterating; unstable assumptions about sort).
- [ ] **A5 — manifest.yaml + map.** `introduces: [set-literal, set-ops, tuple, sorted-key]`;
  `requires:` trimmed to genuinely-used Book-1/U01–U03; `practices:` = scanner-derived features
  (`str-split`, plus any of dict-literal/dict-access/list-sort/in-operator actually used) + hand-listed
  `input-parse`; `practices ∩ introduces = ∅`. Copy the same lists into the coverage-map U04 entry
  (manifest == map).
- [ ] **A6 — verify U04 in isolation:** `--book book2` manifest/structure/hygiene/cell-lint/noexec/
  stretch/prereq/coverage/concept-scan/exec-solutions/exec-lessons all PASS; concept-scan confirms all four
  introduced features are detected as USED and nothing untaught leaks (esp. no `bitwise-ops`).

### Phase B — U05 "Searching & Complete Search" (3 lessons)

**Files:**
- Create: `book2/units/unit-05-searching-complete-search/{lesson,exercises,solutions}.ipynb`
- Create: `book2/units/unit-05-searching-complete-search/teacher-notes.md`
- Create: `book2/units/unit-05-searching-complete-search/manifest.yaml`
- Modify: `book2/curriculum/coverage-map.yaml` (fill the U05 entry's `practices`)

**Interfaces:**
- Consumes: U04's `sorted-key`/`tuple` + Book-1 (list-index, while-loop, for-loop, nested-loops,
  comparison, arithmetic, int-type).
- Produces: techniques `binary-search`, `complete-search` (prereqs for CP1 and later units).

- [ ] **B1 — lesson.ipynb.** Hook: "is target X present among N sorted values — and can you answer 10⁵
  queries fast?" Teach: (1) linear search (baseline, O(n)); (2) **binary search** — sort first, then
  iterative `lo/hi/mid` narrowing, the loop invariant, and the classic count/lower-bound framing; (3)
  **complete search** — fixed-depth nested loops enumerating all pairs / triples / candidate values within
  constraints, with the O(n²)/O(n³) cost tied back to U03. Explicit NOTE cell: this unit does NOT generate
  subsets/permutations (that needs recursion — U09). `no-exec` wrapper cell. Closure-safe surface only.
- [ ] **B2 — exercises.ipynb.** ≥ 8 `## Exercise N` `solve(data)` problems that REQUIRE search/enumeration
  and are non-trivial (constraints force it): binary-search presence/count/lower-bound, "does any pair sum
  to T" via sort+two-index-scan or nested loop, all-pairs closest, triple with a property (small N),
  smallest feasible value by search-over-answer. ≥ 2 `stretch`. EMPTY student cells; Sample I/O +
  Constraints; decisive value last / last-after-sort.
- [ ] **B3 — solutions.ipynb.** Mirror headings; pure `solve(data)`; binary-search solutions use
  `lo/hi/mid`; complete-search uses fixed-depth nested loops (NO subset generation). Non-vacuous asserts
  incl. target-absent, target-at-both-ends, empty-answer, boundary (target == first/last element), and
  off-by-one on the search bounds (mid rounding, `lo <= hi` vs `<`).
- [ ] **B4 — teacher-notes.md.** Five headings; per-exercise Big-O (search O(log n) after O(n log n) sort;
  enumeration O(n²)/O(n³)); 3-lesson pacing (L1 linear+binary search; L2 complete search / all-pairs;
  L3 search-over-the-answer + mixed practice); common mistakes (binary-search off-by-one; forgetting to
  sort; enumerating with the wrong depth; O(2ⁿ) subset temptation — defer to U09).
- [ ] **B5 — manifest.yaml + map.** `introduces: [binary-search, complete-search]`; `requires:` trimmed to
  genuinely-used; `practices:` = scanner-derived features (`str-split`, `sorted-key`/`tuple`/`set-ops` if
  used) + hand-listed `input-parse`; `practices ∩ introduces = ∅`; manifest == map U05 entry.
- [ ] **B6 — verify U05 in isolation** (same check list as A6); concept-scan clean; confirm NO premature
  feature (e.g. no `comprehension`) and that binary-search/complete-search are the only new techniques,
  both listed under `introduces`.
