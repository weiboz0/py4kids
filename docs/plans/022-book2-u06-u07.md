# Plan 022 — Book 2 U06 "Greedy" + U07 "Simulation & Ad Hoc"

**Goal:** Ship the first two Term-2 units — `unit-06-greedy` (introduces the TECHNIQUE `greedy`) and
`unit-07-simulation` (introduces the TECHNIQUE `simulation`) — on the `solve(data:str)->str` contract,
following the established Book-2 technique-unit pattern (U02/U03/U05).

**Architecture:** Two units, each the standard Book-2 set (lesson/exercises/solutions/teacher-notes/
manifest). Both introduced concepts are reviewer-enforced **techniques** (scanner-invisible in both
directions), taught in the lesson + teacher-notes and reinforced by the exercises. U06 greedy =
sort-then-sweep / locally-best choice; U07 simulation = follow-the-rules step-by-step state (including on a
grid). Graded exercises are `solve(data)` problems that REQUIRE the technique (a correct greedy choice; a
faithful simulation). Wire each into ci-local via the existing Book-2 per-entry block (auto-covers new
unit dirs).

**Tech Stack:** Jupyter notebooks (nbformat), `tools/` checks, `scripts/ci-local.sh`,
`py4kids-tools --book book2`; Python 3 stdlib only.

**Spec:** `docs/designs/001-book2-algorithms.md` (§4 unit anatomy, §5 two-tier concepts, §7 U06/U07);
`book2/syllabus.md`; `book2/curriculum/coverage-map.yaml` (U06/U07 entries); `book2/curriculum/
concepts.yaml`; plans 018–021 (the shipped Book-2 unit pattern — all closure rules transfer); the
plan-019/020/021 content-gate lessons (mutation categories; `.remove` ban; untaught-builtin ban;
one-directional concept-scan; the corrected set-ops recipe).

## Global Constraints

Copied from the design + registry + prior-gate lessons; every task's requirements include this section.

- **Contract:** every reference solution is a pure `solve(data: str) -> str`; ZERO `input()` in any
  executable cell; the submission wrapper `import sys; print(solve(sys.stdin.read()))` appears ONLY in a
  `no-exec`-tagged LESSON cell (allowed for units — cell-lint exempts `no-exec` for `kind=="unit"`) or in
  teacher-notes; NEVER in solutions.ipynb (exec-solutions runs every cell). Deterministic. Student code
  cells are EMPTY (`''`).
- **New concepts are TECHNIQUES (scanner-invisible):** `greedy` (U06) and `simulation` (U07) are
  reviewer-enforced — taught genuinely in the lesson/teacher-notes and USED by the exercises; each is
  hand-listed nowhere as a practice of its own unit (it is that unit's `introduces`). A used technique from
  an EARLIER unit must be hand-listed in practices; a not-yet-introduced technique must NOT appear.
- **Closure (same scanner rules as U02–U05):** only Book-1 + U01–U0(N-1) concepts + this unit's introduce.
  If sets are used: set-ops ONLY via `.add`/`.discard` on a `{…}`/`set()` var in-cell, or `-`; **NOT
  `.remove`** (scanner silently credits it, but U04 taught only `.add`/`.discard`); NEVER `&|^`; NEVER
  `.union`/`.intersection`/`.difference`. `sorted(seq, key=named_fn)` (NO lambda). binary-search
  `lo/hi/mid` and fixed-depth nested-loop complete-search are allowed (taught U05). **Nothing not yet
  taught:** no `prefix-sum` (U08, a technique — reviewer-caught), no converging two-pointer (U14, a
  technique — reviewer-caught); and no not-yet-taught FEATURE — `recursion`/`backtracking` (U09), `deque`
  (U10), `comprehension`/generator expressions (U09), `bitwise-ops`/`base-conversion` (U11) — these ARE
  scanner-detectable, so concept-scan reds them as used-but-unlisted. NO untaught methods
  (.join/.splitlines/.index/.count/.find/.pop). Allowed builtins ONLY `{len,min,max,sorted,sum,abs,round}` —
  NO `all`/`any`/`enumerate`/`zip`/`reversed`/`map`/`filter`. **Enforcement split:** concept-scan +
  ad-hoc `detect()` catch premature FEATURES + untaught methods; the `.remove` ban and the untaught-builtin
  ban (`all`/`any`/`enumerate`/`zip`/`reversed`/`map`/`filter`) are scanner-BLIND (bare-name calls / a
  silently-credited method) and must be enforced by **grep + reviewer read**, not `detect()`. concept-scan
  `--book book2` clean.
- **Two-tier `practices` — the plan-020 formula:** `practices = (detected ∪ manually-listed used
  concepts) − requires − introduces − wrapper-artifacts (file-read, import-statement)`. A concept already in
  the unit's `requires` NEVER also appears in `practices` (so U06 keeps `sorted-key`/`tuple` in `requires`
  only; U07 keeps `input-parse`/`grid-2d` in `requires` only). What remains in `practices`: `str-split`
  (feature, if used and not in requires) + any earlier TECHNIQUE used and not in requires (`complexity`/
  `binary-search`/`complete-search`/`boolean-algebra`) + the Book-1 concepts used. `requires ∩ practices =
  ∅` and `practices ∩ introduces = ∅` (matching U01–U05); manifest == coverage-map exactly. Derive
  `str-split`/features from an ad-hoc `detect()` over the three notebooks; hand-add scanner-invisible used
  concepts (`dict-access` via `.get`/`[]`; techniques).
- **Rich, laddered problem sets:** ≥ 8 `## Exercise N` per unit (tooling counts `^## Exercise \d+`), each
  with Sample Input / Sample Output / Constraints; ≥ 2 cell-tagged `stretch` (heading "Challenge"); core
  content never depends on stretch. Non-vacuous asserts: sample + crafted edge cases killing off-by-one
  (drop-last / range(n-1)), wrong-aggregate/tie boundary, self-pair, and **decisive-last-AFTER-SORT** for
  any sort-then-scan/greedy solution. Decisive values placed last (and last-after-sort).
- **teacher-notes:** exactly the five heading strings `## Goals`/`## Pacing`/`## Common mistakes`/
  `## Discussion prompts`/`## Differentiation`; a per-exercise Big-O line; a pacing plan covering all
  allocated lessons (U06 = 2, U07 = 2).

## Out of scope

- No checkpoint (CP2 is a later plan — it assesses U06–U08 and needs all three merged first).
