# Plan 022 — Book 2 U06 "Greedy" + U07 "Simulation & Ad Hoc"

**Goal:** Ship the first two Term-2 units — `unit-06-greedy` (introduces the TECHNIQUE `greedy`) and
`unit-07-simulation` (introduces the TECHNIQUE `simulation`) — on the `solve(data:str)->str` contract,
following the established Book-2 technique-unit pattern (U02/U03/U05).

**Architecture:** Two units, each the standard Book-2 set (lesson/exercises/solutions/teacher-notes/
manifest). Both introduced concepts are reviewer-enforced **techniques** (scanner-invisible in both
directions), taught in the lesson + teacher-notes and reinforced by the exercises. U06 greedy =
sort-then-sweep / locally-best choice; U07 simulation = follow-the-rules step-by-step state (including on a
grid). Graded exercises are `solve(data)` problems that REQUIRE the technique (a correct greedy choice; a
faithful simulation). Wire each into ci-local via the existing Book-2 per-entry block (auto-covers new
unit dirs).

**Tech Stack:** Jupyter notebooks (nbformat), `tools/` checks, `scripts/ci-local.sh`,
`py4kids-tools --book book2`; Python 3 stdlib only.

**Spec:** `docs/designs/001-book2-algorithms.md` (§4 unit anatomy, §5 two-tier concepts, §7 U06/U07);
`book2/syllabus.md`; `book2/curriculum/coverage-map.yaml` (U06/U07 entries); `book2/curriculum/
concepts.yaml`; plans 018–021 (the shipped Book-2 unit pattern — all closure rules transfer); the
plan-019/020/021 content-gate lessons (mutation categories; `.remove` ban; untaught-builtin ban;
one-directional concept-scan; the corrected set-ops recipe).

## Global Constraints

Copied from the design + registry + prior-gate lessons; every task's requirements include this section.

- **Contract:** every reference solution is a pure `solve(data: str) -> str`; ZERO `input()` in any
  executable cell; the submission wrapper `import sys; print(solve(sys.stdin.read()))` appears ONLY in a
  `no-exec`-tagged LESSON cell (allowed for units — cell-lint exempts `no-exec` for `kind=="unit"`) or in
  teacher-notes; NEVER in solutions.ipynb (exec-solutions runs every cell). Deterministic. Student code
  cells are EMPTY (`''`).
- **New concepts are TECHNIQUES (scanner-invisible):** `greedy` (U06) and `simulation` (U07) are
  reviewer-enforced — taught genuinely in the lesson/teacher-notes and USED by the exercises; each is
  hand-listed nowhere as a practice of its own unit (it is that unit's `introduces`). A used technique from
  an EARLIER unit must be hand-listed in practices; a not-yet-introduced technique must NOT appear.
- **Closure (same scanner rules as U02–U05):** only Book-1 + U01–U0(N-1) concepts + this unit's introduce.
  If sets are used: set-ops ONLY via `.add`/`.discard` on a `{…}`/`set()` var in-cell, or `-`; **NOT
  `.remove`** (scanner silently credits it, but U04 taught only `.add`/`.discard`); NEVER `&|^`; NEVER
  `.union`/`.intersection`/`.difference`. `sorted(seq, key=named_fn)` (NO lambda). binary-search
  `lo/hi/mid` and fixed-depth nested-loop complete-search are allowed (taught U05). **NO not-yet-taught
  technique: no `prefix-sum` (U08), no recursion/backtracking (U09), no `deque` (U10), no converging
  two-pointer (U14).** NO comprehensions/generator expressions (`comprehension` is U09). NO untaught
  methods (.join/.splitlines/.index/.count/.find/.pop). Allowed builtins ONLY `{len,min,max,sorted,sum,
  abs,round}` — NO `all`/`any`/`enumerate`/`zip`/`reversed`/`map`/`filter`. concept-scan `--book book2`
  clean; confirm no premature FEATURE via ad-hoc `detect()` (concept-scan is one-directional).
- **Two-tier `practices`:** scanner-derived FEATURES (`str-split`, plus `sorted-key`/`tuple`/`set-ops` if
  used) + hand-listed earlier TECHNIQUES (`input-parse`, `grid-2d`, and any of `complexity`/`binary-search`/
  `complete-search`/`boolean-algebra` a solution genuinely uses) + the Book-1 concepts used, minus wrapper
  artifacts (`file-read`, `import-statement`). `practices ∩ introduces = ∅`; `requires ∩ practices = ∅`
  (matching U01–U05); manifest == coverage-map exactly. Derive from an ad-hoc `detect()` over the three
  notebooks; hand-add scanner-invisible used concepts (`dict-access` via `.get`/`[]`; techniques).
- **Rich, laddered problem sets:** ≥ 8 `## Exercise N` per unit (tooling counts `^## Exercise \d+`), each
  with Sample Input / Sample Output / Constraints; ≥ 2 cell-tagged `stretch` (heading "Challenge"); core
  content never depends on stretch. Non-vacuous asserts: sample + crafted edge cases killing off-by-one
  (drop-last / range(n-1)), wrong-aggregate/tie boundary, self-pair, and **decisive-last-AFTER-SORT** for
  any sort-then-scan/greedy solution. Decisive values placed last (and last-after-sort).
- **teacher-notes:** exactly the five heading strings `## Goals`/`## Pacing`/`## Common mistakes`/
  `## Discussion prompts`/`## Differentiation`; a per-exercise Big-O line; a pacing plan covering all
  allocated lessons (U06 = 2, U07 = 2).

## Out of scope

- No checkpoint (CP2 is a later plan — it assesses U06–U08 and needs all three merged first).
- **Verification is NOT out of scope:** Phase C is the named verification phase (blind-solve + mutation +
  full ci-local + 4-way content gate).

## Phases

### Phase A — U06 "Greedy" (2 lessons)

**Files:**
- Create: `book2/units/unit-06-greedy/{lesson,exercises,solutions}.ipynb`, `teacher-notes.md`, `manifest.yaml`
- Modify: `book2/curriculum/coverage-map.yaml` (fill the U06 entry's `practices`)

**Interfaces:**
- Consumes: U04 `sorted-key`/`tuple` + Book-1 (for-loop, accumulator, comparison, list-sort).
- Produces: technique `greedy` (prereq for CP2 and later units).

- [ ] **A1 — lesson.ipynb.** Contest hook (e.g. "attend the most non-overlapping events" or "make change
  with fewest coins where greedy is valid"). Teach: the greedy pattern = sort by the right key, then sweep
  taking the locally-best choice; an informal "why it works" (exchange argument in plain words); and a
  caution that greedy is NOT always correct (one counter-example). Runnable `solve(data)` cells; one
  `no-exec`-tagged cell showing the wrapper.
- [ ] **A2 — exercises.ipynb.** ≥ 8 `## Exercise N`, each a `solve(data)` problem where a correct greedy
  choice (with the right sort key) solves it: interval scheduling / max non-overlapping, minimize-lateness,
  fractional-knapsack-style ratio pick, fewest-coins (valid denominations), assign-to-minimize, deadline
  ordering. ≥ 2 `stretch`. EMPTY student cells; Sample I/O + Constraints; decisive value last / after sort.
- [ ] **A3 — solutions.ipynb (FRESH author, blind).** Mirror `## Exercise N`; pure `solve(data)`; each uses
  `sorted(seq, key=named_fn)` + a sweep. Non-vacuous asserts incl. tie at the sort boundary,
  decisive-last-after-sort, and a case where a naive non-greedy/wrong-key choice differs.
- [ ] **A4 — teacher-notes.md.** Five exact headings; per-exercise Big-O (dominated by the O(n log n) sort);
  2-lesson pacing (L1 the pattern + why-it-works; L2 harder greedy + a counter-example); common mistakes
  (wrong sort key; assuming greedy always works).
- [ ] **A5 — manifest.yaml + map.** `introduces: [greedy]`; `requires:` trimmed to genuinely-used;
  `practices:` = scanner features (`str-split`, `sorted-key`, `tuple` if used) + hand-listed `input-parse`
  + Book-1 used; `practices ∩ introduces = ∅`, `requires ∩ practices = ∅`; manifest == map.
- [ ] **A6 — verify U06 in isolation:** all `--book book2` checks PASS; concept-scan clean (no premature
  technique/feature — ad-hoc `detect()` shows no `prefix-sum`-ish feature leak, and reviewers confirm no
  premature technique); greedy genuinely taught + used.

### Phase B — U07 "Simulation & Ad Hoc" (2 lessons)

**Files:**
- Create: `book2/units/unit-07-simulation/{lesson,exercises,solutions}.ipynb`, `teacher-notes.md`, `manifest.yaml`
- Modify: `book2/curriculum/coverage-map.yaml` (fill the U07 entry's `practices`)

**Interfaces:**
- Consumes: Book-1 (for/while loops, if, list, accumulator) + U01 `grid-2d`/`input-parse`.
- Produces: technique `simulation` (prereq for CP2 and later units).

- [ ] **B1 — lesson.ipynb.** Hook: "follow the rules exactly" (e.g. a robot on a grid, a queue of events,
  a game of steps). Teach: model the state, apply each rule/step in order, watch the edges (bounds,
  off-by-one, termination). Runnable `solve(data)` cells (incl. a grid walk using `grid-2d`); one
  `no-exec` wrapper cell.
- [ ] **B2 — exercises.ipynb.** ≥ 8 `## Exercise N` `solve(data)` problems that REQUIRE faithful
  step-by-step simulation: grid robot / bounded walk, tick-by-tick resource/state update, event queue
  processing, wrap-around counter, rule-driven transformation. ≥ 2 `stretch`. EMPTY student cells;
  Sample I/O + Constraints; decisive value last; a case exercising the boundary/termination edge.
- [ ] **B3 — solutions.ipynb (FRESH author, blind).** Mirror `## Exercise N`; pure `solve(data)`;
  fixed-depth loops / bounded while-loops (guaranteed to terminate); NO recursion. Non-vacuous asserts incl.
  the boundary/edge/termination case, off-by-one on the last step, and wrong-order-of-operations.
- [ ] **B4 — teacher-notes.md.** Five exact headings; per-exercise Big-O (typically O(steps) or O(R·C));
  2-lesson pacing (L1 state + one-step rules; L2 grid/queue simulation + edges); common mistakes
  (off-by-one on the final step; updating state in the wrong order; missing a boundary).
- [ ] **B5 — manifest.yaml + map.** `introduces: [simulation]`; `requires:` trimmed; `practices:` = scanner
  features (`str-split`) + hand-listed `input-parse`/`grid-2d` + Book-1 used; disjointness as A5; manifest
  == map.
- [ ] **B6 — verify U07 in isolation** (same check list as A6); concept-scan clean; confirm NO premature
  technique/feature and that `simulation` is the only new technique.
