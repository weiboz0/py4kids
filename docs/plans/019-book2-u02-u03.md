# Plan 019 — Book 2 U02 "Boolean Logic & Algebra" + U03 "Fast Enough? (Complexity)"

**Goal:** Ship the two conceptual Term-1 foundation units — `unit-02-boolean-logic`
(boolean-algebra + code-tracing) and `unit-03-complexity` (Big-O) — following the U01 Book-2 content
pattern, adapted for concept-heavy (ACSL-style) units whose new concepts are TECHNIQUES, not language
features.

**Architecture:** Two units, each the standard Book-2 unit set (lesson/exercises/solutions/
teacher-notes/manifest) on the `solve(data:str)->str` contract; the introduced concepts
(`boolean-algebra`, `code-tracing`, `complexity`) are taught/reinforced in the lesson + teacher-notes
(they are reviewer-enforced techniques — `concept-scan` cannot see them). Graded exercises are
`solve(data)` problems that USE boolean logic (U02) or REQUIRE the efficient approach (U03). Wire each
into ci-local via the existing Book-2 per-entry block (already covers all authored units).

**Spec:** `docs/designs/001-book2-algorithms.md` (§3-4, §7 U02/U03); `book2/syllabus.md`;
`book2/curriculum/coverage-map.yaml` (U02/U03 entries); **plan 018 (the established Book-2 unit
pattern — all of it transfers)**; the plan-018 content-gate lessons (mutation-test asserts for
off-by-one; do not edit files under review).

## Global Constraints

- **The Book-2 unit pattern (from plan 018, binding — applies to both units):** `solve(data:str)->str`
  pure functions, ZERO `input()` in executable cells; submission wrapper ONLY in a `no-exec`-tagged
  lesson cell / teacher-notes; `exercises.ipynb` uses `## Exercise N` headings (≥8, ≥2 `stretch`;
  each with statement + Constraints + Sample Input/Output; empty student cells); `solutions.ipynb`
  mirrors `## Exercise N` with **non-vacuous sample+edge asserts (mutation-test off-by-one — a wrong
  parse/bound must fail; every parsing exercise needs a case whose DECISIVE value is at the last
  position)**; `teacher-notes.md` = FIVE headings (`## Goals`/`## Pacing`/`## Common mistakes`/
  `## Discussion prompts`/`## Differentiation`) + per-exercise Big-O + pacing covering ALL allocated
  lessons; manifest map-equal (`requires` genuinely-used; `practices ∩ introduces` empty).
- **`practices` = FEATURES scanner-derived + TECHNIQUES reviewer-derived (sol BLOCKER).** The scanner
  is invisible to techniques in BOTH directions, so `practices` cannot be "scanner-derived" alone:
  1. **Features:** scanner-derive as in U01. NOTE (glm-2): these units USE `.split` but do NOT
     introduce it, so **`str-split` (a FEATURE, introduced by U01) MUST appear in U02/U03 `practices`**
     or `concept-scan` reds — U01 only got away with Book-1-only practices because it *introduces*
     `str-split`.
  2. **Techniques:** the AUTHOR HAND-LISTS every technique the unit genuinely practices — notably
     **`input-parse`** (a technique, introduced by U01), which every `solve(data)` parsing unit uses;
     add it to `practices` (legal: introduced-by-U01, `practices ∩ introduces` empty). This also gives
     `input-parse` a machine-visible pre-capstone practice home.
  3. **No premature technique:** the unit MUST NOT USE a not-yet-introduced technique. Concretely
     **U03 must NOT use `binary-search`** (U05's introduce) to demonstrate O(log n) — teach O(log n)
     CONCEPTUALLY (repeated halving / guess-the-number), NOT a list binary-search implementation
     (fable-3/sol). The scanner cannot catch this; the CONTENT GATE manually rejects any unlisted-used
     OR premature technique.
- **Untaught SURFACE FORBIDDEN — methods AND builtins (glm-3):** no `.join`/`.splitlines`/`.index`/
  `.count`/`.find` (methods), AND **no untaught builtins `all`/`any`/`enumerate`/`zip`/`reversed`**
  (bare-name calls slip the scanner, which flags only attribute calls — `any`/`all` especially tempt
  U02's boolean aggregation). Use explicit loops/accumulators. No `random`, no files.
- **Available concept surface:** Book-1 baseline + U01's `input-parse`/`str-split`/`grid-2d` (U01
  precedes these units). U02/U03 may NOT use any not-yet-introduced Book-2 feature (no sets/tuples/
  `sorted(key=)`/recursion/…). No new language FEATURE is introduced by either unit → `concept-scan`
  will detect only Book-1 + U01 features; the introduced concepts are techniques.
- **U02 concept scope:** introduces `boolean-algebra` + `code-tracing` (both TECHNIQUES). The LESSON
  teaches: truth tables, the logic operators (`and`/`or`/`not` — Book-1 `logical-ops`), De Morgan's
  laws, short-circuit evaluation, and simplifying boolean expressions; plus a recurring **code-tracing
  ("what does this print?")** warm-up. Exercises are `solve(data)` problems that genuinely exercise
  boolean logic (e.g. evaluate a rule over N yes/no inputs; decide a condition combining several
  flags; a small truth-table / voting / access-control decision). `requires` = boolean, logical-ops,
  comparison, if-statement, elif-else, print, variable (all Book-1). Reviewers confirm the lesson
  genuinely teaches boolean-algebra + code-tracing (techniques aren't scanner-checked).
- **U03 concept scope:** introduces `complexity` (TECHNIQUE). The LESSON teaches: counting operations,
  O(n)/O(n²)/O(log n), reading the constraints to judge "will it finish?", when brute force survives.
  Exercises are `solve(data)` problems where the constraints demand the efficient approach (an O(n) or
  O(n log n)-shaped solution; an O(n²) would conceptually time out) — but all solutions stay pure
  functions verified on small samples (CI can't enforce time limits; each exercise's intended Big-O is
  stated in teacher-notes). `requires` = for-loop, nested-loops, list-loop, list-literal, range-function.
  1 lesson (per the map); pacing is a single lesson.
- **CI-safety:** solutions run headless input-free; verified sample+edge asserts. ci-local already runs
  the Book-2 per-entry checks over all authored units — no ci-local change needed (the new unit dirs
  are picked up automatically).
- Process (standing): no commits while a `[sol]` review is in flight; **do NOT edit files while any
  reviewer is mid-review** (plan-018 lesson); SEPARATE codex sessions for STATEMENTS vs blind
  SOLUTIONS per unit; confirm each codex bg task COMPLETED before verifying (subagent-race).
