**Goal:** Ship the final two Term-4 content units — `unit-13-grids-graphs` (introduces the TECHNIQUES
`graph-repr`, `bfs`, `dfs`, `flood-fill`) and `unit-14-two-pointers` (introduces the TECHNIQUE
`two-pointers`) — on the `solve(data:str)->str` contract, following the established Book-2 unit pattern.
These are the last new concepts before the capstone (`project-03`).

**Architecture:** Two units, each the standard Book-2 set (lesson/exercises/solutions/teacher-notes/
manifest). U13 teaches 2D-grid neighbour/bounds logic, **explicit graphs as adjacency-list dicts** (NO
class), **flood-fill** / connected components, **BFS** shortest-steps (a `deque` used as a FIFO queue —
`append` to enqueue, `popleft` to dequeue), and **DFS** reachability (recursion from U09, or a `deque`
stack). U14 teaches the **two-pointer** pattern: converging pointers on a sorted list and the sliding-window
sum/count. All five are reviewer-enforced TECHNIQUES (no new AST-detected feature). Graded exercises REQUIRE
the technique. Wire each into ci-local via the existing Book-2 per-entry block.

**Tech Stack:** Jupyter notebooks (nbformat), `tools/` checks, `scripts/ci-local.sh`,
`py4kids-tools --book book2`; Python 3 stdlib only (`from collections import deque` for BFS/DFS-stack).

**Spec:** `docs/designs/001-book2-algorithms.md` §7 (Term 4) + §5 (graphs as adjacency-list dicts, NO class);
`book2/syllabus.md`; `book2/curriculum/coverage-map.yaml` (U13/U14 entries); `book2/curriculum/concepts.yaml`
(all five new ids are `kind: technique`); plans 018–027 (the shipped pattern + ALL closure/gate lessons,

## Global Constraints

Copied from the design + registry + prior-gate lessons; every task's requirements include this section.
**This plan introduces the LAST new techniques — after U14 every concept is taught.**

- **Contract:** every reference solution is a pure `solve(data: str) -> str`; ZERO `input()` in any
  executable cell; the submission wrapper appears ONLY in a `no-exec`-tagged LESSON cell (units get the
  `kind=="unit"` cell-lint exemption) or teacher-notes; NEVER in solutions.ipynb. Deterministic. Student
  code cells are EMPTY (`''`). Every cell has an `id`. Every output is an INTEGER or plain string — never a
  float.
- **NEWLY LEGAL here (the units' teaching targets, all scanner-invisible TECHNIQUES):** `graph-repr`
  (adjacency-list dict, NO class), `bfs`, `dfs`, `flood-fill` (U13); `two-pointers` (U14). These reuse
  features already taught: `deque` (U10 — BFS queue is `append`+`popleft`; a DFS stack is `appendleft`+
  `popleft`), `recursion` (U09 — recursive DFS/flood-fill), `set-literal` (U04 — a `visited` set via `{…}`/
  `set()` + `.add` + `in`), `grid-2d` (U01), `dict-literal`/`dict-access` (Book-1). **DFS/flood-fill
  accumulate through a `visited` set or a result list PASSED AS AN ARGUMENT and mutated (`.add`/`.append`) —
  NEVER via `nonlocal`/`global`.**
- **STILL BANNED until their unit (U13 content only):** in U13, `two-pointers` (converging pointers OR a
  sliding window) is U14 — not yet. (U14 content may freely use the U13 graph techniques.)
- **ALWAYS BANNED (course-wide — the full accumulated list):** **NO `nonlocal` / `global`** (taught nowhere
  in Book 1/2, invisible to concept-scan — grep for them; DFS passes state as an argument instead). **NO
  `.pop()`** (untaught — a stack/queue is a `deque` with `appendleft`/`append`/`popleft`; peek `stack[0]`).
  **NO `comprehension`** (dropped from Book 2 — AST-check `ListComp`/`SetComp`/`DictComp`/`GeneratorExp`).
  **NO augmented assignment `+=`/`-=`/… (use `x = x + …`).** NO `del`. NO list/string repetition `[x]*n`/
  `'0'*n` (build the visited grid / distance array with `while`/`append`). NO chained comparison `a<=b<c`
  (use `0 <= r and r < rows`). set-ops via `.add`/`.discard`/`-` only (NEVER `.remove`/`&|^`-on-sets/
  `.union`/`.intersection`/`.difference`). NO untaught methods (`.join`/`.splitlines`/`.index`/`.count`/
  `.find`/`.pop`). NO untaught stdlib (`itertools`, `collections.Counter`, `math.*`) and NO base/number
  shortcuts (`bin`/`hex`/`format`/`:b`/`0x`/3-arg `pow`/`divmod`). Allowed builtins ONLY
  `{len,min,max,sorted,sum,abs,round}` — NO `all`/`any`/`enumerate`/`zip`/`reversed`/`map`/`filter`.
  **Output assembly:** `.join` banned → build multi-item output ONE concat per statement (`result = result +
  piece`; the multi-concat `result = result + a + " " + b` form is O(n²) — the 439 s U11-Ex6 trap — so NEVER
  use it). concept-scan `--book book2` clean.
- **Enforcement split:** concept-scan + ad-hoc `detect()` confirm no premature/unlisted FEATURE (the new
  concepts are techniques — scanner-invisible — so detect() should show only the LISTED features
  `deque`/`recursion`/`set-literal`/`tuple`/`str-split` etc., each in requires/practices). An **AST check**
  for comprehensions, augmented-assignment (`ast.AugAssign`), list/str-repetition (`ast.BinOp` Mult with a
  List/Str operand), chained comparison (`ast.Compare` len(ops)>1); plus a **grep (code cells only)** for
  `\bnonlocal\b`, `\bglobal\b`, `\.pop\(`, `\.remove\(`, `\bdel\b`, `\.join\(`, `itertools`, `Counter`,
  `\bmath\b`, the banned builtins. The TECHNIQUES (`graph-repr`/`bfs`/`dfs`/`flood-fill`/`two-pointers`) are
  enforced by an APPROACH audit (adjacency dict, NO class; BFS uses a deque FIFO queue; DFS recursion/stack
  with a passed-in visited; two-pointers genuinely advances two indices / a window — not a nested-loop brute
  force that ignores the technique).
- **Two-tier `practices` (plan-020 formula):** `practices = (detected ∪ manually-listed used) − requires −
  introduces − wrapper-artifacts (file-read, import-statement)`. `requires ∩ practices = ∅`,
  `practices ∩ introduces = ∅`; manifest == coverage-map exactly (incl. list order). Derive from ad-hoc
  `detect()`; hand-add scanner-invisible used concepts (techniques, `dict-access`, `input-parse`).
- **Rich, laddered problem sets:** ≥ 8 `## Exercise N` per unit (tooling counts `^## Exercise \d+`), each
  with Sample Input / Sample Output / Constraints; ≥ 2 cell-tagged `stretch`. Non-vacuous asserts killing
  each technique's signature mutant — BFS: the shortest-distance value (a wrong FIFO order / revisiting
  inflates it), an unreachable target (→ the stated "impossible" sentinel), a decisive-last cell;
  flood-fill: a single region, two disjoint regions, a diagonal NON-connection (4-neighbour only); DFS
  reachability: a reachable and an unreachable node, a cycle (visited prevents infinite recursion);
  graph-repr: a degree/neighbour query where an undirected edge must appear on BOTH endpoints; two-pointers:
  the converging-pointer pair that is decided at the LAST step, an empty/sentinel window, a window whose
  answer sits at the right boundary. Decisive values last. **Bound grid/graph sizes so recursive DFS depth
  is safe** (state a height/size cap; deep recursion → `RecursionError`).
- **teacher-notes:** exactly the five heading strings `## Goals`/`## Pacing`/`## Common mistakes`/
  `## Discussion prompts`/`## Differentiation`; a per-exercise Big-O line; a concept → core-exercise matrix
  (≥1 non-stretch exercise per introduced technique); a pacing plan covering all allocated lessons

### Phase A — U13 "Grids, Graphs & Traversal" (3 lessons)

**Files:** Create `book2/units/unit-13-grids-graphs/{lesson,exercises,solutions}.ipynb`, `teacher-notes.md`,
`manifest.yaml`; Modify `book2/curriculum/coverage-map.yaml` (U13 entry).

**Interfaces:** Consumes U01 `grid-2d`, U04 `set-literal`, U09 `recursion`, U10 `deque`, Book-1 dict/list.
Produces techniques `graph-repr`, `bfs`, `dfs`, `flood-fill` (prereqs for the capstone).

- [ ] **A1 — lesson.ipynb.** Hook (e.g. "fewest steps through a maze" / "how many rooms are connected?").
  Teach: (1) a 2D grid — neighbours (up/down/left/right), bounds checks (`0 <= r and r < rows`, no chained
  comparison); (2) an explicit graph as an **adjacency-list dict** `{node: [neighbours]}` built with
  `dict`/`list-append` (NO class, NO comprehension), degree = `len(adj[node])`, undirected edge added to
  BOTH endpoints; (3) **flood-fill** — recursively (or with a stack) fill a region, marking a `visited` set;
  (4) **BFS** shortest-steps — a `deque` FIFO queue (`append` enqueue, `popleft` dequeue), a `visited` set,
  a distance dict/array; (5) **DFS** reachability — recursion with a `visited` set **passed as an argument**
  (never `nonlocal`). Runnable `solve(data)` cells (bounded sizes); one `no-exec` wrapper cell.
- [ ] **A2 — exercises.ipynb.** ≥ 8 `## Exercise N` `solve(data)` problems REQUIRING the techniques, ≥1
  core per introduced technique (graph-repr, bfs, dfs, flood-fill): maze/grid shortest-steps (BFS),
  count-regions / largest-region (flood-fill, 4-neighbour), reachability / connected? (DFS), a
  degree/neighbour query on an adjacency-list graph (graph-repr), grid "can escape?" (BFS/DFS). ≥ 2
  `stretch`. EMPTY student cells; Sample I/O + Constraints (BOUND sizes so recursion is safe; state the
  unreachable/"impossible" sentinel); integer/string outputs; the signature edges per Global Constraints;
  decisive value last.
- [ ] **A3 — solutions.ipynb (FRESH author, blind).** Mirror `## Exercise N`; pure `solve(data)`; adjacency
  dict (NO class); BFS with `deque` `append`/`popleft`; DFS recursion (or `deque` stack `appendleft`/
  `popleft`) with a `visited` set passed as an argument; flood-fill marking a visited set/grid built by
  `while`/`append`. NONE of `nonlocal`/`global`/`.pop`/`del`/`.join`/comprehension/`+=`/list-or-str-rep/
  chained-comparison/banned-builtins. Bounded depth. Non-vacuous asserts per the signature list.
- [ ] **A4 — teacher-notes.md.** Five exact headings; per-exercise Big-O (BFS/DFS O(V+E); flood-fill O(cells);
  grid O(R·C)); concept → core-exercise matrix; 3-lesson pacing (L1 grids + adjacency graphs; L2 flood-fill +
  BFS; L3 DFS + harder); common mistakes (forgetting `visited` → infinite loop / RecursionError; BFS using a
  LIFO stack instead of a FIFO queue gives wrong distances; diagonal vs 4-neighbour; mutating the grid while
  iterating; reaching for `.pop`/`nonlocal`).
- [ ] **A5 — manifest.yaml + map.** `introduces: [graph-repr, bfs, dfs, flood-fill]`; `requires:` trimmed to
  genuinely-used; `practices:` per the formula; disjointness; manifest == map (incl. order).
- [ ] **A6 — verify U13 in isolation:** all `--book book2` checks PASS; concept-scan clean; ad-hoc `detect()`
  shows only LISTED features (no premature/unlisted); AST-check (no comprehension/`+=`/list-or-str-rep/
  chained-comparison); **grep (code cells) for `\bnonlocal\b`, `\bglobal\b`, `\.pop\(`, `\.remove\(`,
  `\bdel\b`, `\.join\(`, banned builtins** — all absent; approach audit (adjacency dict NO class, BFS deque
  FIFO, DFS visited-as-argument, 4-neighbour); each technique has a core exercise.

### Phase B — U14 "Two Pointers & Sliding Window" (2 lessons)

**Files:** Create `book2/units/unit-14-two-pointers/{lesson,exercises,solutions}.ipynb`, `teacher-notes.md`,
`manifest.yaml`; Modify `book2/curriculum/coverage-map.yaml` (U14 entry).

**Interfaces:** Consumes Book-1 (list-index/while/accumulator/comparison) + U04 `sorted-key`. Produces
technique `two-pointers`.

- [ ] **B1 — lesson.ipynb.** Hook (e.g. "find two prices that sum to the budget" / "longest stretch under a
  limit"). Teach: (1) converging two pointers on a SORTED list — `lo`/`hi` moving inward by comparison
  (pair-sum, closest pair); (2) the sliding window — `left`/`right` indices bounding a contiguous run, with a
  running sum/count updated as the window grows/shrinks (longest/shortest window meeting a condition). Stress
  WHY it is linear vs the nested-loop brute force. Runnable `solve(data)` cells; one `no-exec` wrapper cell.
- [ ] **B2 — exercises.ipynb.** ≥ 8 `## Exercise N` REQUIRING two-pointers/sliding-window: pair summing to
  a target on a sorted list, count pairs under a threshold, longest window with sum ≤ K, shortest window
  summing ≥ K, a converging-pointer decision. ≥ 2 `stretch`. EMPTY student cells; Sample I/O + Constraints;
  the signature edges (decided-at-last-step, empty/boundary window, answer at the right boundary); decisive
  value last.
- [ ] **B3 — solutions.ipynb (FRESH author, blind).** Mirror `## Exercise N`; pure `solve(data)`; genuine
  two-pointer / sliding-window index advancement (NOT a disguised nested-loop brute force); `sorted(key=…)`
  where a sort is needed (no lambda); NONE of `nonlocal`/`.pop`/`del`/`.join`/comprehension/`+=`/
  list-or-str-rep/chained-comparison/banned-builtins. Non-vacuous asserts per the signature list.
- [ ] **B4 — teacher-notes.md.** Five exact headings; per-exercise Big-O (O(n) window / O(n log n) if a sort
  dominates); concept → core-exercise matrix; 2-lesson pacing (L1 converging pointers; L2 sliding window);
  common mistakes (advancing the wrong pointer; off-by-one on the window bounds; forgetting to shrink the
  window; re-summing the window each step instead of updating incrementally → O(n²)).
- [ ] **B5 — manifest.yaml + map.** `introduces: [two-pointers]`; `requires:` trimmed; `practices:` per the
  formula; disjointness; manifest == map.
- [ ] **B6 — verify U14 in isolation:** all `--book book2` checks PASS; concept-scan clean; AST + grep
  (including `\bnonlocal\b`) as in A6; approach audit (genuine two-pointer/window advancement, not a nested
  loop); each technique has a core exercise.
