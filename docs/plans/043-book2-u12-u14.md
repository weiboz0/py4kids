## Closure discipline (preserve what each unit already teaches)

- **U12 Binary Trees** introduces technique `tree-traversal`; REQUIRES `recursion` (U09). A tree is
  **parallel arrays** (`value[]`, `left[]`, `right[]`) with a **`-1` child sentinel**, base-cased with
  `== -1` BEFORE indexing (never `arr[-1]`, which silently reads the last element). **No class.**
  Recursion lives in NESTED helpers (`preorder`/`inorder`/`postorder`/`score`/`contains`/`insert`/
  `valid`) — **never `nonlocal`/`global`**; pass state as arguments or build a returned string.
  Graded traversals are PRE/POST-order (in-order of a BST is just `sorted()`).
- **U14 Two Pointers** introduces technique `two-pointers`. Converging pointers on a SORTED list
  (`lo`/`hi` moving inward) + sliding window with an INCREMENTAL running sum; **window problems need
  NON-NEGATIVE values** so shrinking is safe. Iterative (no recursion). Plain loops/lists/ints.
- **All units:** pinned source-policy builtins `{len,min,max,sorted,sum,abs,round,input,print,range,
  int,str,set}`; no `.pop/.join/.index/.count/.find`, `+=`/AugAssign, chained compare, `[x]*n`,
  comprehension, ternary `IfExp`, `del`/`global`/`nonlocal`. AST-verify after transform.

## U12 — Binary Trees & Traversals (introduces `tree-traversal`; lessons:2)

Restore the school-record project hook in cell 0 (from `main`).

- **L1 — store a tree without classes; recursive traversal & aggregation.** THREE fresh rungs, each a
  Notice: (1) parallel-array nodes (`value`/`left`/`right`), read a child, and stop at the `-1`
  sentinel; (2) a recursive PRE-order walk building a visit string (base case `node == -1`);
  (3) recursive AGGREGATION — a helper that RETURNS a number up the tree (e.g. height or a subtree sum),
  base case returns 0/identity. Then **Put it together** `l1.py` = the pre-order traversal solver
  (lesson cell 2), `no-exec` + run line + complexity `O(n)`.
- **L2 — binary search trees.** THREE fresh rungs: (1) the BST property (left < node < right) and a
  membership walk going left/right by comparison (a FRESH literal-data variant, distinct from the `l2`
  mirror); (2) build a BST by recursive insertion from `root =
  -1`; (3) validate with a `(low, high)` bound passed down. Then **Put it together** `l2.py` = the BST
  membership solver (lesson cell 8), `no-exec` + run line + complexity `O(h)`.
- **Closure:** introduces tree-traversal; requires recursion + parallel-array/int/str/print; `-1`
  sentinel base-cased before indexing; no class, no `nonlocal`.

## U14 — Two Pointers & Sliding Window (introduces `two-pointers`; lessons:2)

Restore the project hook in cell 0 (from `main`).

- **L1 — converging two pointers.** THREE fresh rungs: (1) hand-trace `lo`/`hi` on a SORTED list for a
  pair summing to a target (move `lo` up when the sum is too small, `hi` down when too big);
  (2) count/closest variant — track the best while converging; (3) why it is `O(n)` — an EXECUTABLE
  rung that COUNTS pointer moves on a literal list and prints the total (≈ n), showing each pointer moves
  one way only. Then **Put it together** `l1.py` = the converging pair-search solver (lesson cell 3,
  found-flag flat transform), `no-exec` + run line + complexity **`O(n)`** (the input is already sorted;
  the solver does NOT sort — the `O(n log n)` sort belongs to `ex4`, which sorts by a key).
- **L2 — sliding window.** THREE fresh rungs: (1) grow a window and keep a running sum over NON-NEGATIVE
  values; (2) shrink from the left while the window is over budget (longest-affordable); (3) the reverse
  goal — shortest window reaching a target. Then **Put it together** `l2.py` = the sliding-window solver
  (lesson cell 9), `no-exec` + run line + complexity `O(n)`.
- **Closure:** introduces two-pointers; requires sorted-key/list/while/accumulator; window values
  non-negative; iterative, no banned construct.
