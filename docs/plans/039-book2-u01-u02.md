## U01 — Reading the Input (introduces `input-parse, str-split, grid-2d`)

The lesson REFRAMES around reading real stdin. Open project-first (contest hands you text; print exact
text). Teach that the real program starts `import sys` / `data = sys.stdin.read()`, then parses.

- **L1 — read values from stdin.** Executable literal-data rungs (each a `**Notice:**`): `.split()` a
  literal `data` string into tokens → `int(token)` → "read N then N values" with a position loop →
  build exact output text (space-join via a loop). Then **Put it together** `l1.py` = the sum-&-maximum
  stdin solver (`data = sys.stdin.read()`; parse N + values; `print(f"{total} {biggest}")`), shown
  `no-exec` + run line + complexity `O(n)`.
- **L2 — read a grid from stdin.** THREE one-increment executable rungs (sol blocker — do not bundle):
  (1) parse the `R C` header into two ints; (2) read ONE row of `C` ints with a token-position counter
  (single loop) and print it; (3) loop `R` rows into a list-of-lists (nested loops, `grid-2d`) and index
  one cell `grid[r][c]`. Then **Put it together** `l2.py` = a grid row-sums stdin solver (grid row-sums
  shape; **use sample data DIFFERENT from exercise 5** so ex5 isn't answered verbatim — fable nit),
  `no-exec` + run line + complexity `O(R*C)`. Completeness: the existing decisive-last / border edge
  notes.
- **Closure:** union introduces input-parse/str-split/grid-2d; requires def/parameters/return/for/
  list/int/type-conversion/print; allowed builtins incl. `sum`/`max`/`len`/`range`/`int`/`str`/`print`/
  `input`. `input-parse`/`grid-2d` are techniques (reviewer); `.split` is str-split. No banned
  construct.

## U02 — Boolean Logic & Algebra (introduces `boolean-algebra, code-tracing`)

Keep the executable truth-table / De-Morgan / short-circuit / simplification demos as ladder rungs
(they already print + assert the equivalences — that verification IS the completeness "why", the
boolean analog of a counterexample). Keep the two code-tracing warm-ups.

- **L1 — boolean algebra.** Rungs (≥3): truth table for `and`/`or`; `not` + precedence + **code-tracing
  warm-up 1** (stays in L1 — fable nit); De Morgan (print + assert both laws agree every row);
  short-circuit; simplify `not(not(member or guest) or banned)` → `(member or guest) and not banned`
  (assert equivalence every row). **Put it together** `l1.py` = a gate-access stdin solver
  (`member guest banned` → `GRANTED`/`DENIED` via the simplified form), `no-exec` + run line + complexity `O(1)` (fixed inputs).
- **L2 — code-tracing & deciding.** THREE one-increment rungs before the solver (sol blocker):
  (1) **code-tracing warm-up 2** (the gate checker, predict-then-run); (2) count yes-answers over a
  literal list with an accumulator + print the count; (3) GENERALIZE — detect a dissenter (`found_no`)
  and combine the two facts with `and` (`yes_count*2 > n and found_no`) on literal data, printing the
  decision. Then **Put it together** `l2.py` = the majority-with-a-dissenter stdin solver, `no-exec` +
  run line + complexity `O(N)` + a note on the strict-majority `*2` idiom. **`.lower()`: state in the l2 problem that
  answers may be mixed-case (`Yes`/`NO`) and add a mixed-case fixture so `.lower()` is load-bearing
  (else drop it) — glm/fable.**
- **Closure:** union introduces boolean-algebra/code-tracing; requires boolean/logical-ops/comparison/
  if/elif-else/print/variable; allowed builtins; `.lower` is a taught string method (used in the
  majority solver — confirm it's in the practices/allowed set, else avoid it). No banned construct.
