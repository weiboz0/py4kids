# How to Use This Book

Begin with Getting Set Up.
Each unit then opens with a contest problem and teaches the ideas you need to solve it.
Read the lesson, run its programs, and then solve the exercises yourself.

## Reading the page

- **Program / Output:** Program shows Python code; Output shows what it prints.
- **Notice:** A short explanation of the idea the example just used.
- **Try it yourself:** A complete program that reads its input; run it with the sample input shown next to it.
- **Challenge:** An optional stretch problem; later units do not depend on it.
- **Constraints:** The limits on the input, such as the largest N. They tell you how fast your program must be.
- **Sample Input / Sample Output:** One test case and the exact output your program must print for it.
- **You will learn / Recap:** A short guide to the unit's goals and a reminder of what you can now do.

## Contest programs read their input

Every problem in this book reads its whole input from standard input, the way contest judges run programs.
To test a program, save the sample input in a text file and send it to your program:

```text
python my_solution.py < case.txt
```

On Windows you may need `py` instead of `python`; on a Mac, `python3`.
Getting Set Up shows how to open a terminal in the right folder.
Your program must print exactly the sample output: the same numbers, spaces, and lines, and nothing else.
Do not print prompts such as `Enter a number:`.

## Check your work

Make each program pass its samples first.
Then read the constraints and invent your own tests: the smallest input, the largest, all values equal, and any case the statement singles out.
Ask whether your program does too much work for the largest input before you trust it.

## Mock Contests

The four Mock Contests are timed practice papers: set a timer, work without notes, and check each program against its samples when time is up.
